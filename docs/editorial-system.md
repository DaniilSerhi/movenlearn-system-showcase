# Editorial system

The miniature case answers one bounded question: how does a participant prepare a human review request in a fictional demo service?

Read the files in order:

1. [Research brief](../demo/editorial/research-brief.md): intent, scope and source needs.
2. [Claim ledger](../demo/editorial/claim-ledger.md): accepted facts, sources and rejected claims.
3. [Article brief](../demo/editorial/article-brief.md): reader, structure and next action.
4. [Final article](../demo/editorial/final-article.md): a concise, sourced explanation.
5. [QA checklist](../demo/editorial/qa-checklist.md): what to verify before release.

The article is backed by included fictional policy fixtures. It demonstrates traceability, not live research into university rules. A real admissions article would require current primary sources and human source review.

Writing constraints: no empty introductions, invented expertise, unsupported claims, keyword stuffing, length targets used as filler or repetitive summary structures. A next step belongs where it follows from the reader's task. The example has one local action and makes no sale.

The wider editorial approach includes locale parity. This miniature is English only and does not demonstrate translation QA.
